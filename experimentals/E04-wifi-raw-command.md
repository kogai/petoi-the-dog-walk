# E04: Wi-Fi 経由で、動作名の表に無い文字列も送れるか

- 依頼日: 2026-09-25
- 実施日:

## 目的

公式の Wi-Fi スケッチのコードを読むと、`/action?name=<文字列>` は、文字列が動作名の表に無ければ**そのまま**シリアルへ送る（[F-B8](../docs/design/facts.md)）。
つまりトークン（`ksit` など）も送れるはずだが、手元の ESP8266 に書き込まれたスケッチが同じものかは分からない。
実機で次を確かめる。

1. トークンを `name` にそのまま入れて、その通りに動くか
2. 応答の本文に、Bittle がシリアルに返した文字列が入るか（F-B8 では 40ms 以内に読めた分）
3. `name=stop` で止まるか（表では `d`）

結果で、`HttpTransport` が何を送り、成否をどう判定するか（[06-transport.md](../docs/design/06-transport.md) 2節）が決まる。

## 必要なもの

- 機材: Bittle、ESP8266 モジュール（公式サンプルを書き込み済み）。**持っていなければ、結果の「判定」に「対象外」と書いて終わってよい**
- ソフトウェア: `curl`（macOS に入っている）
- 先に E00 の手順 B を済ませておく（IP アドレスと、`stop` で止まるかが分かる）
- 所要時間の目安: 20分

## 安全上の注意

- Bittle を平らな床に置き、周囲 2m 以内に物・段差が無いことを確認する。
- 止めるときは、次を実行する。止まらなければ電源を切る。
  ```sh
  curl -sS --max-time 5 "http://<IP>/action?name=stop"
  ```
  `stop` で止まるかはまだ確かめていない（**未確認**。E00 の手順 B で分かる）。**E00 で `stop` で止まらなかった場合、止め方は電源を切ることだけになる。その場合は手順 2 のうち、トークンの行（`ksit`・`kbalance`）だけを試し、手順 3 は行わない。**

## 手順

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。`<IP>` は E00 の手順 B で調べた IP アドレスに置き換える。
**IP は結果に貼らない。** エラーの表示（`Failed to connect to ...` など）にも IP やホスト名が出るので、伏せる。
出力は `experimentals/raw/` に保存する（中身はコミットされない）。
以下のコマンドは **未実行**。

1. 手元のスケッチが公式のものかを確かめる。書き込んだときのスケッチのファイルがあれば、その `sendCmd` 関数が次と同じかを見る（無ければ「不明」と記録して先へ進む）。
   - 公式のコード: `name` が動作名の表に無ければ `Serial.print(argname)` でそのまま送る（F-B8 の出典のリンク先）
2. 動作名とトークンを、同じ動作について比べる。各コマンドは、応答の本文と HTTP ステータスを表示する（5 秒で打ち切る）。
   ```sh
   for name in sit ksit balance kbalance; do
     echo "== $name"
     curl -sS --max-time 5 -o - -w '\nHTTP %{http_code}\n' "http://<IP>/action?name=$name"
     sleep 3
   done 2>&1 | tee experimentals/raw/e04-tokens.txt
   ```
   各コマンドの後の Bittle の動きを記録する（`sit` と `ksit` はどちらも座る、`balance` と `kbalance` はどちらも立つ、が期待）。
3. 止める。`stop` の応答と動きを記録する。
   ```sh
   curl -sS --max-time 5 -o - -w '\nHTTP %{http_code}\n' "http://<IP>/action?name=stop" 2>&1 | tee experimentals/raw/e04-stop.txt
   ```

関節の直接指定（首を動かすなど）は、この実験では行わない。設計にまだ使い道が無いため（06 の `Token` の許可リストにも無い）。

## 判定基準

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| トークン（手順 2） | `ksit` と `kbalance` の両方で、動作名と同じように動いた（動作名を試さなかった場合は、期待した動き（座る・立つ）をした） | `HttpTransport` もトークンを `name=` にそのまま入れて送る。06 の 2節の表の `HttpTransport` の行を「`name=` にトークンを入れる」に直す。F-B8 を実機でも確かめたと記録する |
| トークン（手順 2） | 動作名では動くが、トークンでは動かない（片方だけ動いた場合も含む） | `HttpTransport` は動作名に変換して送る（F-B8 の表を使う）。Wi-Fi 経路では、スキルは表にある動作の並びに限る |
| 応答（手順 2） | 本文に Bittle の返した文字列が入っている | `HttpTransport` は本文で成否を判定する（E00 のシリアルの応答と同じ形なら、同じ判定を使う） |
| 応答（手順 2） | 本文が空か、いつも同じ | `HttpTransport` は HTTP のエラーと時間切れだけを失敗とする |
| 停止（手順 3） | `stop` で止まった | `HttpTransport::stop` は `name=stop`（またはトークン `d`）を送る |
| 停止（手順 3） | `stop` で止まらなかった | Wi-Fi 経路は安全に止められない。`HttpTransport` は作らず、シリアル経路だけにする |
| （全体） | ESP8266 を持っていない（対象外） | `HttpTransport` は今の設計（動作名で送る）のまま保留し、フェーズ2では作らない。シリアル経路を先に作る |
| （全体） | 手順どおりに進まなかった・判定できない | 再依頼する。それまで `HttpTransport` は作らない |
