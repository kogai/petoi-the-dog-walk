# E04: Wi-Fi 経由で、決まった動作名以外を送れるか

- 状態: 依頼中（ESP8266 モジュールを持っている場合のみ）
- 依頼日: 2026-09-25
- 実施日:
- 実施者:

## 目的

公式の Wi-Fi サンプルは `http://<IP>/action?name=<動作名>` を受け、決まった動作名をシリアルコマンドに変換する（F-B5）。
トークンそのもの（`ksit` など）や、関節の直接指定を送れるかを確かめる。
送れない場合は、Wi-Fi 経路では `actions.h` の動作名だけを使う設計にする（06-transport.md）。

## 必要なもの

- 機材: Bittle、ESP8266 モジュール（公式サンプルを書き込み済み）
- ソフトウェア: `curl`
- 所要時間の目安: 20分

## 安全上の注意

- 関節の直接指定は、予想外の姿勢になることがある。Bittle を床に置き、手を近づけない。

## 手順

1. E00 の手順 B が動くことを確認する。
2. 次を順に実行し、HTTP ステータス・応答本文・Bittle の動きを記録する。
   ```sh
   curl -sv "http://<IP>/action?name=ksit"
   curl -sv "http://<IP>/action?name=kbalance"
   ```
3. 書き込んだ ESP8266 のスケッチ（公式サンプル）のソースを見て、`name` 以外の引数や、
   任意の文字列をそのままシリアルへ流す経路があるかを確認し、あればその URL を記録する。
4. 3 で経路が見つかった場合だけ、首を少し動かす程度の関節指定を1回だけ試す
   （コマンドの書き方は [Serial Protocol](https://docs.petoi.com/apis/serial-protocol.md) を参照）。

## 記録すること

- [ ] 手順2の結果
- [ ] スケッチのバージョンまたは取得元 URL
- [ ] 任意の文字列を流す経路の有無（ソースの該当箇所）
- [ ] 手順4の結果（実施した場合）

## 判定基準

| 結果 | 設計への影響 |
|---|---|
| トークンをそのまま送れる | `HttpTransport` もトークンで統一する |
| 動作名だけ送れる | `HttpTransport` は動作名へ変換して送る。スキルは動作名の並びに限る |
