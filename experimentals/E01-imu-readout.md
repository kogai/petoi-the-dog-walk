# E01: 標準ファームのまま、IMU の値を Mac から読めるか

- 状態: 依頼中
- 依頼日: 2026-09-25
- 実施日:
- 実施者: （GitHub のユーザー名）

## 目的

基板上の IMU（MPU6050、F-B2）の値を、標準ファームのまま Mac から読めるかを確かめる。
読めれば、転倒・持ち上げの検知（[D-01](../docs/design/decisions.md) 安全上の例外、D-02 反射の対象）と、
Jev に渡す `situation`（[03-reasoning-layer.md](../docs/design/03-reasoning-layer.md) 2節）に使える。
どのくらいの頻度で読めるかで、反射層（100ms 周期）の入力に使えるかも決まる。

## 必要なもの

- 機材: Bittle（標準ファーム）、シリアル経路（USB / Bluetooth）。Wi-Fi 経路しか無い場合は、結果に「実施できない」と書いて終わってよい
- ソフトウェア: E00 と同じ道具 [`e00-serial-probe`](../crates/walk-experiments/src/bin/e00-serial-probe.rs)（E00 の手順 A-1 でビルド済みであること）
- **先に E00 を済ませておく**（道具が実機で動くこと、ポートを開いたときに基板が再起動するかどうかが分かる）
- できれば2人（1人が Bittle を持ち、もう1人がキーボードを操作する）
- 所要時間の目安: 40分

## 安全上の注意

- この実験では、Bittle を手で持ち上げる・傾ける・裏返す。
- **ポートを開くのは、必ず床に置いた状態で行う。** 開いたときに基板が再起動し、サーボが動くことがある（E00 で分かる）。
- 道具は、終わるとき・`Ctrl-C` を押したときに停止トークン `d` を送る。**`d` を受けると脚が休みの姿勢へ動く見込み**（**未確認**）。道具が終わる前に床に置く。
- 持つときは胴の中央を持ち、脚を自分の体と顔から外に向ける。関節に指を入れない。
- 始める前に電源スイッチの位置を確かめておく。**サーボが予想外に動いたら、床に置いて電源を切る。**
- `!! STOP TOKEN NOT SENT` と表示されたら、すぐ電源を切る。`Ctrl-Z` は使わない。
- `g`（IMU の切り替え、F-T1）を送ると姿勢の制御が変わり、サーボが動き出すことがある。手順 5 は床に置いたまま行う。途中で止めた場合は、電源を入れ直して元に戻す。

## 手順

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。`<PORT>` は E00 で調べたポート名。
出力は `E00_LOG` で `experimentals/raw/` に保存する（コミットされない。`tee` は使わない）。
E00 で `E00_SETTLE_MS` を変えた場合は、同じ値を `export E00_SETTLE_MS=<値>` してから始める。
以下のコマンドは **未実行**（E00 が済むまで、道具は実機で動かしていない）。

1. [Serial Protocol](https://docs.petoi.com/apis/serial-protocol.md) を読み、IMU の値を表示するトークンを探す。
   このリポジトリではまだ確かめていない（候補として `v` があるが **未確認**）。見つけたトークンと、ドキュメントの該当箇所を記録する。
   以下の `<IMU>` は、見つけたトークンに置き換える。見つからなければ `v` で試す。
   - 道具が受け付けるのは、1〜16 文字の英数字だけ。見つけたトークンに空白や記号（引数など）が入っていて道具が受け付けなかったら、
     そのトークンを記録して、ここで止める（道具を直して再依頼する）。
2. 床の上で1回。値が出ることを確かめる。
   ```sh
   E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-floor.txt ./target/release/e00-serial-probe <PORT> <IMU> <IMU> <IMU>
   ```
3. 姿勢を変えながら読む。**床に置いたままコマンドを始め**、`->` が表示されるたびに次の姿勢へ移る（8 秒ごと）。
   ```sh
   E00_WAIT_MS=8000 E00_FINAL_WAIT_MS=3000 E00_LOG=experimentals/raw/e01-postures.txt ./target/release/e00-serial-probe <PORT> <IMU> <IMU> <IMU> <IMU> <IMU>
   ```
   | `->` の回 | その時の姿勢（`->` が出る前に作っておく） |
   |---|---|
   | 1 回目 | 床に置いたまま |
   | 2 回目 | 水平のまま持ち上げて、静止 |
   | 3 回目 | Bittle から見て右側（右の脚）を下げて、45 度くらい傾けて静止 |
   | 4 回目 | 裏返して静止 |
   | 5 回目 | 床に戻す |
   最後の `->` の後、3 秒で `d` が送られる。それまでに床に戻しておく。
4. 読み取りの頻度を調べる。床に置いたまま行う。
   - 4a. 問い合わせを繰り返す方式: `<IMU>` を 0.1 秒おきに 10 回送る。
     ```sh
     E00_WAIT_MS=100 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-poll.txt ./target/release/e00-serial-probe <PORT> <IMU> <IMU> <IMU> <IMU> <IMU> <IMU> <IMU> <IMU> <IMU> <IMU>
     ```
     10 回の送信それぞれに値が返ったか、送ってから値が返るまでの時間（`->` と `<-` の時刻の差）を記録する。
   - 4b. 連続表示の方式: ドキュメントに、値を出し続けさせるトークンがあれば、それを `<STREAM>` として送り、5 秒後にもう一度送る（止めるため）。
     **1 回目の送信の後、床から持ち上げて、また床に置く**（持ち上げる動作の最中の値を見るため）。
     ```sh
     E00_WAIT_MS=5000 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-stream.txt ./target/release/e00-serial-probe <PORT> <STREAM> <STREAM>
     ```
     1 秒あたりの回数は「5 秒間に出た値の数 ÷ 5」で数える（道具の `<-` の1行が、値1回分とは限らない）。
     連続表示のトークンが無ければ「無し」と記録する。
5. `g` の前後で表示や動きが変わるかを見る。床に置いたまま、1 回の実行で `<IMU>` → `g` → `<IMU>` → `g`（元に戻す）の順に送る。
   ```sh
   E00_WAIT_MS=2000 E00_LOG=experimentals/raw/e01-gyro.txt ./target/release/e00-serial-probe <PORT> <IMU> g <IMU> g
   ```

## 判定基準

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| 姿勢（手順 3） | 床・傾き・裏返しがはっきり区別できる | IMU を読み取りに入れる。D-01（転倒時の安全上の例外）を検討できる。D-02 の候補に「転倒」を残す |
| 姿勢（手順 3） | 傾き・裏返しは区別できるが、静止した「持ち上げ」は床と区別できない | 転倒は候補に残す。持ち上げは静止した値では検知できないので、手順 4b の「動作の最中の値」で判断する |
| 姿勢（手順 3） | 値は出るが、どの姿勢も区別できない | 値の意味を調べ直す（別のトークン、単位）。それまで D-01・D-02 は保留 |
| 姿勢（手順 1〜3） | 値を表示するトークンが見つからない、または何も返らない | 標準ファームでは読めない。D-01・D-02 の候補から IMU を外すか、ファームの改造を検討する |
| トークン（手順 1） | 見つけたトークンを道具が受け付けなかった | 道具を直して再依頼する。判定は保留 |
| 持ち上げ（手順 4b） | 持ち上げる動作の最中に値がはっきり変わる | D-02 の候補に「持ち上げ」を残す（連続表示で検知する） |
| 頻度（手順 4a・4b） | 問い合わせ・連続表示のどちらかで、1 秒に 10 回以上、取りこぼし無く読める | 反射層（100ms 周期）の入力に使える |
| 頻度（手順 4a・4b） | どちらの方式でも 1 秒に 10 回未満、または取りこぼしがある | 理性層の `situation` にだけ使う。反射層の入力には使わない |
| `g`（手順 5） | 表示や動きが変わる | `g` の意味を facts.md に記録し、本体では送らない（または明示的に扱う） |
| `g`（手順 5） | 変わらない | 記録だけする |
| （全体） | 手順どおりに進まなかった・判定できない | 再依頼する。それまで D-01・D-02 は保留のまま |
