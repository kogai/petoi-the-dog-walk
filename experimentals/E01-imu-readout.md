## 目的

基板上の IMU（MPU6050、F-B2）の値を、標準ファームのまま Mac から読めるかを確かめる。
読めれば、転倒の検知（[D-01](../docs/design/decisions.md) 安全上の例外、D-02 反射の対象）と、Jev に渡す `situation`（[03-reasoning-layer.md](../docs/design/03-reasoning-layer.md) 2節）に使える。
どのくらいの頻度で読めるかで、反射層（100ms 周期）の入力に使えるかも決まる。

この実験では確かめないこと:

- 持ち上げる動作の最中の値（D-02 の「持ち上げ」）。持ち上げながら画面を見ることになり、1人では行えないため（README のルール）。別の実験にする（ID は、その依頼の PR で決める）。
- 歩いている最中の値。脚を付けていないため。

## 使うトークン（設計の前提。**実機では未確認**）

公式ファーム OpenCat のソースコード（[`src/OpenCat.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/OpenCat.h)、[`src/reaction.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/reaction.h)、[`src/imu.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/imu.h)。コミット `24563ca`）を読んだ限りでは、次のとおり。Bittle に入っているファーム（起動の表示に `N_260806`）が、このコードと同じかは**未確認**。

- `v`: IMU の値を1回表示する。表示は、ピッチ・ロール（度）、前後方向と左右方向の加速度、上下方向の加速度の5つを、タブで区切った1行。
- `V`: 値を出し続ける表示の入・切を切り替える。入っている間は、IMU の値を読むたびに1行表示する。
- `G`: 姿勢の自動補正（ジャイロによる釣り合い）の入・切を切り替える。`g`: 補正の細かさを切り替える。どちらも、応答として `G` か `g` を返す。

## 必要なもの

- 人数と役目: 1人
- 機材: Bittle（標準ファーム。**脚を付けていない状態**）、USB アダプタ、充電した電池、Mac
- ソフトウェア: mise と Rust（準備の P-0）、このリポジトリ（道具 `e00-serial-probe`）
- 所要時間の目安: 30分

## 安全上の注意

- Bittle を平らな床に置き、周囲 2m 以内に物・段差が無いことを確認する。台の上では行わない。
- この実験では、Bittle を横倒し・裏返しにして**床に置いた状態で**コマンドを実行する。**実行中は Bittle に触らない、持ち上げない。** 姿勢を変えるのは、コマンドが終わってから。
- ポートを開くと基板が起動し直し、起動の途中でサーボが動くことがある（F-B9）。手を Bittle から離してから実行する。
- 道具は、終わるとき・エラーのとき・`Ctrl-C` を押したときに停止トークン `d` を送る。`d` を受けると休む姿勢へ動く見込みがある（推論。**未確認**）。脚が無いので、サーボの軸が回るだけである。
- `G`・`g` を送ると、姿勢の自動補正が切り替わり、サーボが動くことがある（I-7 は床に普通に置いたまま行う）。
- サーボが予想外に動き続けたら、電池のボタンを長押しして電源を切る（E13 の P-4 と同じ）。
- `!! STOP TOKEN NOT SENT` と表示されたら、すぐ電源を切る。`Ctrl-Z` は使わない。`Ctrl-S` は押さない（押したら `Ctrl-C`、それから `Ctrl-Q`）。

## 準備

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。各手順の出力は `E00_LOG=<ファイル>` で `experimentals/raw/` に保存する（中身はコミットされない。`tee` は使わない）。やり直すときは、ファイル名の末尾に `-r2`・`-r3` のように番号を付け、前の回のファイルを残す。

- P-0. Rust を使えるようにする。
  確かめ方: `cargo --version` を実行し、`cargo 1.` で始まる行が表示される。表示されなければ、[E00](E00-connectivity.md) の P-0 に従って入れる。
- P-1. Arduino IDE を終了する（IDE ごと）。
  確かめ方: Dock の Arduino IDE のアイコンの下に点が無い。
- P-2. 道具をビルドする。
  ```sh
  git pull
  cargo build --release -p walk-experiments --bin e00-serial-probe
  ```
  確かめ方: 最後に `Finished` と表示される。
- P-3. 電池を充電し、Bittle に付ける。USB アダプタで Mac とつなぎ、Bittle の電源を入れる。
  確かめ方: P-5 の出力に起動の表示（`* Start *`）が出る。
- P-4. 横倒し・裏返しにしても USB のケーブルが抜けず、引っ張られないことを確かめる。
  確かめ方: Bittle を右側を下にして床に置き、ケーブルに余裕がある。左側・裏返しでも同じ。確かめたら、普通に置き直す。
- P-5. ポートを調べ、起動を待つ時間を設定し、起動と電池を確かめる。**ポート名は結果に貼らない。**
  ```sh
  ./target/release/e00-serial-probe --list
  export E00_SETTLE_MS=8000
  echo "$E00_SETTLE_MS"
  E00_LOG=experimentals/raw/e01-p5.txt ./target/release/e00-serial-probe <PORT> kbalance
  ```
  確かめ方: `--list` に `usbserial` を含む `/dev/cu.` の行がある（それを `<PORT>` に使う）。`echo` で `8000` と表示される。最後の出力で、`* Start *` を含む `<-` の行が1つだけ、`Ready!` の行が最初の `->` より前、`Low power` の行が無い。
  - `* Start *` が2つ以上あるか、`Low power` が出たら、電池を充電してから P-5 をやり直す。
  - ターミナルを開き直したときは、`export` と `echo` からやり直す（F-B9）。

## 手順

### 共通の決まり

- 判定はすべて道具の出力（`->` と `<-` の時刻と中身）で行う。人が見て答える問いは無い。
- 出力に、最初の `->` より前に `* Start *` を含む行が2つ以上ある回（起動の途中で再起動した。F-B15）と、`Low power` の行がある回は使わない。電池を充電し、P-5 を通してから、その回をやり直す。
- 姿勢を作ってからコマンドを実行し、終わるまで触らない。

### I-1. 普通に置いて、値が出るか

床に普通に置いた状態で、`v` を 1 秒おきに3回送る。

```sh
E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i1-flat.txt ./target/release/e00-serial-probe <PORT> v v v
```

`v` の後に、数字がタブで区切られた行が返るかを見る。`?v` が返る、または何も返らない場合は、I-2 以降を行わずに記録して終わる（判定基準の「値」の行）。

### I-2〜I-4. 姿勢ごとに値を読む

それぞれ、姿勢を作って手を離し、倒れないことを確かめてから実行する。1つの実行で姿勢は1つだけ。

- I-2. 右側（Bittle から見て右）を下にして、横倒しに置く。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i2-right.txt ./target/release/e00-serial-probe <PORT> v v v
  ```
- I-3. 左側を下にして、横倒しに置く。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i3-left.txt ./target/release/e00-serial-probe <PORT> v v v
  ```
- I-4. 裏返しに置く（背中を下にする）。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i4-upside.txt ./target/release/e00-serial-probe <PORT> v v v
  ```

終わったら、普通に置き直す。

### I-5. 問い合わせの速さ

普通に置いたまま、`v` を 0.1 秒おきに 10 回送る。

```sh
E00_WAIT_MS=100 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i5-poll.txt ./target/release/e00-serial-probe <PORT> v v v v v v v v v v
```

### I-6. 出し続ける表示の速さ

普通に置いたまま、`V` を送って 5 秒待ち、もう一度 `V` を送って止める。

```sh
E00_WAIT_MS=5000 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i6-stream.txt ./target/release/e00-serial-probe <PORT> V V
```

1 秒あたりの回数は、2つの `-> "V"` の間に出た値の行の数を 5 で割って数える（道具の `<-` の1行が、値1行分とは限らないので、受け取った中身をつないで改行で数える）。

### I-7. `G` と `g` の応答

普通に置いたまま、`G` → `G`（元に戻す）→ `g` → `g`（元に戻す）を 2 秒おきに送る。

```sh
E00_WAIT_MS=2000 E00_LOG=experimentals/raw/e01-i7-gyro.txt ./target/release/e00-serial-probe <PORT> G G g g
```

それぞれに `G` か `g` が返るかを見る。

## 判定基準

使った回だけで判定する（起動の途中の再起動・`Low power` の回は除く）。値の5つの並びは、上の「使うトークン」のとおりと仮定して読む（ソースコードからの推論。**未確認**）。

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| 値（I-1） | `v` の後に、数字がタブで区切られた行が返る | 標準ファームで IMU の値を読める。I-2 以降で中身を確かめる |
| 値（I-1） | `?v` が返る、または何も返らない | このファームでは `v` で読めない（ファームの版が違う見込み）。D-01・D-02 は保留。ファームの版を調べる実験を起こす |
| 値（I-1） | 上のどちらとも言えない（数字でない行が返る、など） | 分からなかった。保留。出力を貼り、エージェントが読み方を調べてから再依頼する |
| 姿勢（I-1〜I-4） | ロールが、普通に置いたとき（I-1）と右・左の横倒し（I-2・I-3）で 45 度以上違い、右と左で符号が逆。裏返し（I-4）では、ロールかピッチの絶対値が 90 度を超える | 姿勢を区別できる。転倒の検知に使える。D-01（転倒時の安全上の例外）を検討できる。D-02 の候補に「転倒」を残す。値の並びと単位を facts.md に F-B として足す |
| 姿勢（I-1〜I-4） | 値は出るが、上の条件に当てはまらない | 分からなかった（値の意味がソースコードの読みと違う）。D-01・D-02 は保留。出力をもとに、値の意味を調べ直して再依頼する |
| 問い合わせ（I-5） | 10 回すべてに値の行が返り、どれも送ってから 100 ms 以内に返る | 問い合わせ方式で 1 秒に 10 回読める。反射層（100ms 周期）の入力に使える見込み |
| 問い合わせ（I-5） | 返らない回がある、または 100 ms を超える回がある | 問い合わせ方式は反射層には遅い。I-6 の結果で決める |
| 出し続ける表示（I-6） | 5 秒間に 50 行以上（1 秒に 10 行以上）出て、2つ目の `V` の後に止まる | 出し続ける方式で反射層の入力に使える |
| 出し続ける表示（I-6） | 1 秒に 10 行未満、または2つ目の `V` の後も止まらない | 出し続ける方式は反射層には使わない（止まらないときは、本体で `V` を使わない） |
| 速さ（I-5・I-6 の合わせ） | どちらの方式でも 1 秒に 10 回に届かない | IMU は理性層の `situation` にだけ使う。反射層の入力には使わない |
| `G`・`g`（I-7） | それぞれに `G` か `g` が返る | ソースコードの読みどおり。応答の意味（補正の入・切）を facts.md に推論として足す。E00 で見えた `G`・`g`（F-B9・F-B10）との関係を調べる |
| `G`・`g`（I-7） | 返らない、または違う応答 | 記録だけする。本体では `G`・`g` を送らない |
| （全体） | 手順どおりに進まなかった、または使える回が足りなかった | 再依頼する。それまで D-01・D-02 は保留のまま |
