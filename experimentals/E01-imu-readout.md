# E01: 標準ファームのまま、IMU の値を Mac から読めるか

## 目的

基板上の IMU（MPU6050、F-B2）の値を、標準ファームのまま Mac から読めるかを確かめる。
読めれば、転倒の検知（[D-01](../docs/design/decisions.md) 安全上の例外、D-02 反射の対象）と、Jev に渡す `situation`（[03-reasoning-layer.md](../docs/design/03-reasoning-layer.md) 2節）に使える。
どのくらいの頻度で読めるかで、反射層（100ms 周期）の入力に使えそうかも分かる。

この実験では確かめないこと:

- 持ち上げる動作の最中の値（D-02 の「持ち上げ」）。持ち上げながら画面を見ることになり、1人では行えないため（README のルール）。E16 として別に行う（[07](../docs/design/07-roadmap.md) の実験の一覧）。
- 歩いている最中の値。脚を付けていないため。

## 使うトークン（ソースコードからの読み。**実機では未確認**）

公式ファーム OpenCat のソースコード（[`src/OpenCat.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/OpenCat.h)、[`src/reaction.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/reaction.h)、[`src/imu.h`](https://github.com/PetoiCamp/OpenCat/blob/24563ca2e0218150f6299d013cd3a20c45433467/src/imu.h)。コミット `24563ca`）を読んだ限りでは、次のとおり。このコードの版の文字列は `N_260806` で、Bittle の起動の表示（F-B9）と同じである。ただし、Bittle に書き込まれたファームが同じ設定でビルドされたかは**未確認**。

- `v`: IMU の値を1回表示する。表示は、ピッチとロール（度）の2つを、タブで区切った1行。加速度の3つも表示する処理があるが、その設定（`READ_ACCELERATION`）はこのコードでは無効になっている。
- `V`: 値を出し続ける表示の入・切を切り替える。入っている間は、IMU の値を読むたびに1行表示する。応答として `V` か `v` を返す。
- `G`: 姿勢の自動補正（ジャイロによる釣り合い）の入・切を切り替える。`g`: 補正の細かさを切り替える。どちらも、応答として `G` か `g` を返す。facts.md の F-T1 の表（公式 Wi-Fi スケッチの `actions.h`）では `g` を「gyro（IMU 切替）」としていて、ソースコードの意味（細かさ）と食い違う。どちらが Bittle で正しいかは、この実験の I-7 の応答で確かめる。facts.md の F-T1 は、結果を反映する PR で直す。
- 次の動きも、ソースコードからの推論（**未確認**）。
  - 起動の最後に `d`（休む姿勢）を受けると、補正が切れて `g` を表示する（F-B9 の `g`・`d` の説明になりうる）。
  - その次のトークンを受けると、補正が入って `G` を表示する（F-B10 の `G` の説明になりうる）。
  - 補正が入っていて、ロールの絶対値が 90 度を超えると、ファームは転倒とみなし、ビープを鳴らして起き上がりのスキル（`rc`）を始める。

## 必要なもの

- 人数と役目: 1人
- 機材: Bittle（標準ファーム。**脚を付けていない状態**）、USB アダプタ、充電した電池、Mac
- ソフトウェア: mise と Rust（準備の P-0）、このリポジトリ（道具 `e00-serial-probe`）
- 所要時間の目安: 30分

## 安全上の注意

- Bittle を平らな床に置き、周囲 2m 以内に物・段差が無いことを確認する。台の上では行わない。
- この実験では、Bittle を横倒し・裏返しにして**床に置いた状態で**コマンドを実行する。**実行中は Bittle に触らない、持ち上げない。** 姿勢を変えるのは、コマンドが終わってから。
- ポートを開くと起動の表示が出る（F-B9。起動し直しているかは**未確認**）。その間にサーボが動くことがある。手を Bittle から離してから実行する。
- 横倒し・裏返しでは、ファームが転倒とみなして起き上がりの動き（`rc`）を始め、サーボが動いて音が鳴ることがある（推論。**未確認**）。脚が無いので、首と前脚付近のサーボの軸が回るだけだが、体が転がることがありうる。周りに物が無いことを確かめる。
- 道具は、終わるとき・エラーのとき・`Ctrl-C` を押したときに停止トークン `d` を送る。`d` を受けると休む姿勢へ動く見込みがある（推論。**未確認**）。
- `G`・`g` を送ると、姿勢の自動補正が切り替わり、サーボが動くことがある（推論。I-7 は床に普通に置いたまま行う）。
- サーボが予想外に動き続けたら、電池のボタンを長押しして電源を切る（E13 と同じ切り方）。
- `!! STOP TOKEN NOT SENT` と表示されたら、すぐ電源を切る。`Ctrl-Z` は使わない。`Ctrl-S` は押さない（押したら `Ctrl-C`、それから `Ctrl-Q`）。

## 準備

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。各手順の出力は `E00_LOG=<ファイル>` で `experimentals/raw/` に保存する（中身はコミットされない。`tee` は使わない）。やり直すときは、ファイル名の末尾に `-r2`・`-r3` のように番号を付け、前の回のファイルを残す。

- P-0. Rust を使えるようにする。
  確かめ方: `cargo --version` を実行し、`cargo 1.` で始まる行が表示される。表示されなければ、[E00](E00-connectivity.md) の P-0 に従って入れる。
- P-1. Arduino IDE を終了する（IDE ごと）。
  確かめ方: Dock の Arduino IDE のアイコンの下に点が無い。
- P-2. 道具をビルドする。
  ```sh
  git pull
  cargo build --release -p walk-experiments --bin e00-serial-probe
  ```
  確かめ方: 最後に `Finished` と表示される。
- P-3. 電池を充電し、Bittle に付ける。USB アダプタで Mac とつなぎ、Bittle の電源を入れる。
  確かめ方: P-5 の出力に起動の表示（`* Start *`）が出る。
- P-4. 横倒し・裏返しにしても、USB のケーブルが抜けず引っ張られず、USB アダプタに体の重さがかからないことを確かめる。電池のボタンの位置も確かめる。
  確かめ方: Bittle を右側を下にして床に置き、ケーブルに余裕がある。左側・裏返しでも同じで、裏返しのとき USB アダプタが床と体に挟まれていない。確かめたら、普通に置き直す。
- P-5. ポートを調べ、起動を待つ時間を設定し、起動と電池を確かめる。**ポート名は結果に貼らない。**
  ```sh
  ./target/release/e00-serial-probe --list
  export E00_SETTLE_MS=8000
  echo "$E00_SETTLE_MS"
  E00_LOG=experimentals/raw/e01-p5.txt ./target/release/e00-serial-probe <PORT> kbalance
  ```
  確かめ方: `--list` に `usbserial` を含む `/dev/cu.` の行がある（それを `<PORT>` に使う）。`echo` で `8000` と表示される。最後の出力で、`* Start *` を含む `<-` の行が1つだけ、`Ready!` の行が最初の `->` より前、`Low power` の行が無い。
  - `* Start *` が2つ以上あるか、`Low power` が出たら、電池を充電してから P-5 をやり直す。
  - ターミナルを開き直したときは、`export` と `echo` からやり直す（F-B9）。

## 手順

### 共通の決まり

- 判定はすべて道具の出力（`->` と `<-` の時刻と中身）で行う。人が見て答える問いは無い。実施する人は、出力を貼るだけでよい。行を数えたり値を読んだりするのは、エージェントが行う。
- 次の回は使わず、電池を充電して P-5 を通してから、やり直す。
  - 出力のどこかに、`* Start *` を含む行が2つ以上ある回（途中で再起動した。F-B15）
  - `Ready!` の行が、最初の `->` より前に無い回（F-B9）
  - `Low power` の行がある回
- 姿勢を作って手を離してからコマンドを実行し、終わるまで触らない。
- 道具は受け取ったものを、タブを `\t`、改行を `\r\n` のように見える形で表示する。値の行は、例えば `<- "1.23\t-0.45\r\n"` のように表示される見込み（推論）。

### I-1. 普通に置いて、値が出るか

床に普通に置いた状態で、`v` を 1 秒おきに3回送る。

```sh
E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i1-flat.txt ./target/release/e00-serial-probe <PORT> v v v
```

### I-2〜I-4. 姿勢ごとに値を読む

それぞれ、姿勢を作って手を離し、倒れないことを確かめてから実行する。1つの実行で姿勢は1つだけ。

- I-2. 右側（Bittle から見て右）を下にして、横倒しに置く。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i2-right.txt ./target/release/e00-serial-probe <PORT> v v v
  ```
- I-3. 左側を下にして、横倒しに置く。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i3-left.txt ./target/release/e00-serial-probe <PORT> v v v
  ```
- I-4. 裏返しに置く（背中を下にする）。
  ```sh
  E00_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i4-upside.txt ./target/release/e00-serial-probe <PORT> v v v
  ```

終わったら、普通に置き直す。

### I-5. 問い合わせの速さ

普通に置いたまま、`v` を 0.1 秒おきに 10 回送る。

```sh
E00_WAIT_MS=100 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i5-poll.txt ./target/release/e00-serial-probe <PORT> v v v v v v v v v v
```

### I-6. 出し続ける表示の速さ

普通に置いたまま、`V` を送って 5 秒待ち、もう一度 `V` を送って止める。

```sh
E00_WAIT_MS=5000 E00_FINAL_WAIT_MS=1000 E00_LOG=experimentals/raw/e01-i6-stream.txt ./target/release/e00-serial-probe <PORT> V V
```

道具が終わった後も、次の実行で表示が流れ続けていたら（I-7 の出力の最初に値の行が並ぶ）、電源を入れ直してから I-7 をやり直す。

### I-7. `G` と `g` の応答

普通に置いたまま、`v` → `G` → `G` → `g` → `g` を 2 秒おきに送る。最初の `v` は、起動後の最初のトークンに返る `G`（F-B10）と、`G` への応答を分けるために入れる。2回目の `G` と `g` は、切り替えを戻すために送る（起動直後の状態に戻るとは限らない。最後の `d` で補正は切れる見込み。推論）。

```sh
E00_WAIT_MS=2000 E00_LOG=experimentals/raw/e01-i7-gyro.txt ./target/release/e00-serial-probe <PORT> v G G g g
```

## 判定基準

使った回だけで判定する（共通の決まりの3つの条件に当てはまる回は除く）。

- 「値の行」は、`->` より後の `<-` の中身をつないで改行で区切ったときの、`\t` で区切られた数字だけの行。値の並びはピッチ・ロールの順と仮定して読む（ソースコードからの推論。**未確認**）。
- あるトークンへの応答は、その `->` から次の `->`（最後のトークンなら道具の `-> "d"`）までに返ったものとする。時刻は、その行の終わりの改行を含む `<-` の行の時刻で測る。
- I-2〜I-4 では、3回の `v` の値がそろっていること（3つのロールの差が 20 度以内、ピッチも同じ）を「姿勢が変わらなかった」とする。角度の差は 360 度を法として小さい方で測る（例: 179 と -179 の差は 2 度）。そろっていない回は、姿勢が途中で変わったとみなして使わない（`rc` で体が転がった場合など）。

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| 値（I-1） | 3つの `v` のすべてに、値の行が返る | 標準ファームで IMU の値を読める。I-2 以降で中身を確かめる |
| 値（I-1） | `?v` が返る、または値の行が返らない | このファームでは `v` で読めない（ビルドの設定が違う見込み）。D-01・D-02 は保留。ファームの版と設定を調べる実験を起こす |
| 値（I-1） | 上のどちらとも言えない（値の行が一部の `v` にだけ返る、数字でない行だけが返る、など） | 分からなかった。保留。出力をもとにエージェントが読み方を調べてから再依頼する |
| 姿勢（I-1〜I-4） | 普通に置いたとき（I-1）は、3回ともロールとピッチの絶対値が 20 度以下。右・左の横倒し（I-2・I-3）は、3回ともロールの絶対値が 45 度以上で、右と左で符号が逆。裏返し（I-4）は、3回ともロールかピッチの絶対値が 90 度を超える | 姿勢を区別できる。転倒の検知に使える。D-01（転倒時の安全上の例外）を検討できる。D-02 の候補に「転倒」を残す。値の並びと単位を、E01 を出典として facts.md に F-B として足す |

| 問い合わせ（I-5） | 10 回すべてに値の行が返り、どれも `->` から 100 ms 以内 | 問い合わせ方式で 1 秒に 10 回読める。反射層（100ms 周期）の入力に使える見込み。使い方（送信との共存）は D-15・D-17 (3) で決める |
| 問い合わせ（I-5） | 返らない回がある、または 100 ms を超える回がある | 問い合わせ方式は反射層には遅い。I-6 の結果で決める |
| 問い合わせ（I-5） | 応答の窓が重なり、どの `v` への応答か決められない | 分からなかった。安全側に倒し、問い合わせ方式は反射層の入力に使わない |
| 出し続ける表示（I-6） | 2つの `-> "V"` の間に値の行が 50 行以上（1 秒に 10 行以上）あり、2つ目の `V` の後に止まる | 出し続ける方式で、1 秒に 10 回読める。反射層の入力に使える見込み。使い方（送信との共存）は D-15・D-17 (3) で決める |
| 出し続ける表示（I-6） | 1 秒に 10 行未満、または2つ目の `V` の後も止まらない | 出し続ける方式は反射層には使わない（止まらないときは、本体で `V` を使わない） |
| 出し続ける表示（I-6） | 行の区切りが崩れて数えられない | 分からなかった。安全側に倒し、出し続ける方式は反射層の入力に使わない |

| `G`・`g`（I-7） | 応答が無い、または違う応答 | 記録だけする。本体では `G`・`g` を送らない |
| `G`・`g`（I-7） | 応答の窓が重なる、などで判断できない | 分からなかった。保留。本体では `G`・`g` を送らない |

| （全体） | 手順どおりに進まなかった、または使える回が足りなかった | 再依頼する。それまで D-01・D-02 は保留のまま |
