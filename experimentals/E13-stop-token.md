# E13: 停止トークン `d` で止まるか

- 状態: 依頼中（未依頼 → 依頼中 → 実施済み → 反映済み）
- 依頼日: 2026-10-16
- 実施日:
- 実施者:

## 目的

歩き方のトークン（`kwkF`）で動いているサーボが、停止トークン `d` で止まるかを確かめる。あわせて、止まるまでのおおよその遅れと、`d` を2回続けて送ったときの様子を記録する。

結果で決まること:

- `d` を停止に使ってよいか（[06-transport.md](../docs/design/06-transport.md) 2節、[ADR-0001](../docs/design/adr/0001-driver-layer.md) 2.6節 S1）。フェーズ 1c（[07](../docs/design/07-roadmap.md)）の前提。
- `d` を2回送っても害が無いか（ADR-0001 S3。今は未確認のまま、送ってよいことにしている）。

この実験では確かめないこと:

- 脚を付けた状態で止まるか。今回は脚を付けていない Bittle で行う。脚を付けたときの振る舞いは E14 で見る。
- 止まるまでの遅れのミリ秒単位の値。人の目では測れないので、「何秒後には止まっていたか」をおおまかに確かめるだけにする。

## 必要なもの

- 人数と役目: 1人（Bittle は床に置いたまま扱う。持ち上げない）
- 機材: Bittle（標準ファーム。**脚を付けていない状態**）、USB アダプタ、充電した電池、Mac
- ソフトウェア: mise と Rust（準備の P-0）、このリポジトリ（`E00_ASK_AFTER_STOP_MS` が入った版。#23 の後）
- 所要時間の目安: 30分

## 安全上の注意

- Bittle を平らな床に置き、周囲 2m 以内に物・段差が無いことを確認する。台の上では行わない。
- **Bittle は床に置いたまま、持ち上げない。** 脚が付いていないので、歩き方のトークンを送ってもその場から動かない（サーボだけが動く）。
- この実験は「`d` で止まらない」ことがありうる実験である。**問いに答えた後もサーボが動いていたら、すぐ電源を切る。**
- 道具（`e00-serial-probe`）は、終わるとき・エラーのとき・`Ctrl-C` を押したとき・ターミナルを閉じたときに `d` を送る。この実験の設定（`E00_ASK_AFTER_STOP_MS`）では、問いの前と、問いを見る 1.5 秒の後に、`d` を1回ずつ送る。
- 次の表示が出たら、すぐ電源を切る。
  - `!! STOP TOKEN NOT SENT`（`d` を送れなかった）
  - `!! SECOND STOP TOKEN NOT SENT`（2回目の `d` を送れなかった。1回目は送った）
- **`Ctrl-Z` は使わない**（道具が一時停止し、`d` が送られないまま動き続ける）。止めるときは `Ctrl-C`。
- **`Ctrl-S` は押さない**。ターミナルの表示が止まる。止まったら、まず `Ctrl-C` を押し、それから `Ctrl-Q` で表示を戻す。
- 起動時に `no independent stop path, refusing to run` と表示されたら、道具は `d` だけを送って終わる。その回は実施できなかったとして記録する。

## 準備

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。各手順の出力は `E00_LOG=<ファイル>` で `experimentals/raw/` に保存する（このフォルダの中身はコミットされない。`tee` は使わない）。道具は同じ名前のファイルを上書きするので、やり直すときは名前の末尾に `-r2`・`-r3` のように番号を付け、前の回のファイルを残す。

- P-0. Rust を使えるようにする。E00 で用意した Mac なら、確かめるだけでよい。
  - 確かめ方: `cargo --version` を実行し、`cargo 1.` で始まる行が表示される。表示されなければ、[E00](E00-connectivity.md) の P-0 に従って入れる。
- P-1. Arduino IDE を終了する（IDE ごと）。
  確かめ方: Dock の Arduino IDE のアイコンの下に点が無い。
- P-2. 道具をビルドする。
  ```sh
  git pull
  cargo build --release -p walk-experiments --bin e00-serial-probe
  ```
  確かめ方: 最後に `Finished` と表示される。続けて次を実行し、`E00_ASK_AFTER_STOP_MS` を含む行が表示される（入っていなければ `git pull` をやり直す）。
  ```sh
  ./target/release/e00-serial-probe 2>&1 | grep E00_ASK_AFTER_STOP_MS
  ```
- P-3. 電池を充電し、Bittle に付ける。USB アダプタで Mac とつなぎ、Bittle の電源を入れる。
- P-4. 置き方を決める。Mac は、画面から目を移すだけで Bittle の前脚付近（首の後ろの肩のあたり）が見える位置に置く。
  確かめ方: 画面を見た姿勢のまま、目だけを動かして前脚付近のサーボが見える。
- P-5. ポートを調べ、起動を待つ時間を設定する。**ポート名は結果に貼らない。**
  ```sh
  ./target/release/e00-serial-probe --list
  export E00_SETTLE_MS=8000
  echo "$E00_SETTLE_MS"
  ```
  確かめ方: `usbserial` を含む `/dev/cu.` の行がある。それを `<PORT>` として以降のコマンドに使う。最後に `8000` と表示される。
- P-6. 起動と電池を確かめる。
  ```sh
  E00_LOG=experimentals/raw/e13-p6.txt ./target/release/e00-serial-probe <PORT> kbalance
  ```
  確かめ方（出力だけを見る）: `* Start *` を含む `<-` の行が1つだけ。`Ready!` の行が、最初の `->` より前に出ている。`Low power` の行が無い。
  - `* Start *` が2つ以上あるか、`Low power` が出たら、電池を充電してから P-6 をやり直す。

## 手順

**どの手順でも**、出力に `* Start *` を含む行が2つ以上ある回（実行中に再起動した）と、`Low power` の行がある回は使わない。電池を充電し、P-6 を通してから、その回をやり直す。答えが `answer: none`・`answer: interrupted` の回、`answer:` の行が無い回も使わず、やり直す。

人が見る理由: 止まったかどうかは、ファームの出力からは分からない（E00 では、`d` に対して `\n\r\n` のような短い応答しか返っていない。F-B11 の `k` のような、動作が終わったしるしは無い）。

問いの答え方（どの手順も同じ）:

1. コマンドを実行したら、画面を見て待つ（Bittle を見ている必要はない）。
2. `>>> LOOK NOW:` が表示されたら、目を Bittle の前脚付近のサーボへ移す。
3. `>>> answer y (yes), n (no) or ? (could not tell), then press Enter:` が表示されたら、`y`（動いている）・`n`（止まっている）・`?`（分からない）のどれかを入力して Enter を押す。
4. 答えた後もサーボが動いていたら、すぐ電源を切る（その回の結果は、そのまま記録する）。

### B-1. 対照: `d` を送らなければ、3 秒後も動いているか

`kwkF` を送り、3 秒後に（`d` を送る前に）問う。B-2 で「止まった」と答えたときに、それが `d` のおかげか、もともと止まる時刻だったのかを見分けるため。2回行う。

```sh
E00_FINAL_WAIT_MS=3000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=3000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

1つずつ実行し、終わってから次を実行する（それぞれ約 15 秒）。2回とも `answer: no` だったら、B-2 以降は行わず、判定基準の「対照」の行に従う。

### B-2. `d` の 2 秒後に止まっているか

`kwkF` を送り、1 秒後に `d` を送る。その 2 秒後（`kwkF` から 3 秒後。B-1 と同じ時刻）に問う。2回行う。

```sh
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

### B-3. `d` の 0.5 秒後に止まっているか

B-2 が2回とも `answer: no` だったときだけ行う。`d` から問いまでを 0.5 秒にする。2回行う。

```sh
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=500 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b3-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=500 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b3-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

問いが出てから目を移すまでに時間がかかるので、実際に見ているのは `d` の 0.5 秒より後になる。「0.5 秒＋目を移す時間」の後の様子として扱う。

### B-4. `d` を2回続けて送る

`kwkF` の 1 秒後に `d` をトークンとして送り、その 0.2 秒後に道具がもう一度 `d` を送る。その 2 秒後に問う。1回行う。

```sh
E00_WAIT_MS=1000 E00_FINAL_WAIT_MS=200 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b4.txt ./target/release/e00-serial-probe <PORT> kwkF d
```

出力では、続けて送った2つの `d`（ログの最初の2つの `-> "d"` の行）のそれぞれに何が返るかを見る。問いの後に、道具が3つ目の `d` を送る。

## 判定基準

使った回だけで判定する（再起動・`Low power`・答えが無い回は除く）。

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| 対照（B-1） | 2回とも `answer: yes`（`d` を送らなければ 3 秒後も動いている） | 対照が成り立つ。B-2 で判定する |
| 対照（B-1） | 2回とも `answer: no` | 対照が成り立たない（`kwkF` は 3 秒より前に自分で止まる）。B-2 は行わない。`d` の効き目は分からなかった。`d` を停止に使うかは保留。時刻を短くした手順で再依頼する（E14 の結果も見る） |

| 停止（B-2、対照が成り立ったとき） | 2回とも `answer: no` | `d` で 2 秒以内に止まる。`d` を停止に使う（06 2節・ADR-0001 S1 のとおり） |

| 停止（B-2、対照が成り立ったとき） | `answer: unknown` がある（`yes` は無い） | 分からなかった。安全側に倒し、`d` を停止に使うかは保留。再依頼する |

| 遅れ（B-3） | `answer: unknown` がある、または B-3 を行わなかった | 分からなかった。遅れの目安は「2 秒以内」（B-2）だけにする |
| 2回の `d`（B-4） | 2つの `d` のどちらにも `?d` のようなエラーの応答が無く、`answer: no` | `d` を重ねて送っても害は見えない。ADR-0001 S3 のとおり |

| 道具 | `!! SECOND STOP TOKEN NOT SENT` や `!! STOP TOKEN NOT SENT` が出た | その回は使わない。道具または接続を調べて直し、再依頼する |
| （全体） | 手順どおりに進まなかった、または使える回が足りなかった | 再依頼する。それまで、フェーズ 1c の前提（`d` で止まる）は未確認のまま |
