# E13: 停止トークン `d` で止まるか

- 状態: 依頼中（未依頼 → 依頼中 → 実施済み → 反映済み）
- 依頼日: 2026-10-16
- 実施日: 2026-10-16（P-6 と B-1a の2回で中止した。結果は「結果」節。状態は依頼中のまま）
- 実施者: kogai

## 目的

歩き方のトークン（`kwkF`）で動いているサーボが、停止トークン `d` で止まるかを確かめる。あわせて、止まるまでのおおよその遅れと、`d` を2回続けて送ったときの様子を記録する。

結果で決まること:

- `d` を停止に使ってよいか（[06-transport.md](../docs/design/06-transport.md) 2節、[ADR-0001](../docs/design/adr/0001-driver-layer.md) 2.6節 S1）。フェーズ 1c（[07](../docs/design/07-roadmap.md)）の前提の一部。
- `d` を2回送っても害が無いか（ADR-0001 S3。今は確かめないまま、送ってよいことにしている）。

この実験では確かめないこと:

- 脚を付けた状態で `d` で止まるか。今回は脚を付けていない Bittle で行う。脚を付けた状態は E14 で確かめる（07 の E14 の行）。フェーズ 1c に進むには、E14 の結果も要る。
- 止まるまでの遅れのミリ秒単位の値。人の目では測れないので、「何秒後には止まっていたか」をおおまかに確かめるだけにする。

## 必要なもの

- 人数と役目: 1人（Bittle は床に置いたまま扱う。持ち上げない）
- 機材: Bittle（標準ファーム。**脚を付けていない状態**）、USB アダプタ、充電した電池、Mac
- ソフトウェア: mise と Rust（準備の P-0）、このリポジトリ（`E00_ASK_AFTER_STOP_MS` が入った版。#23 の後）
- 所要時間の目安: 40分

## 安全上の注意

- Bittle を平らな床に置き、周囲 2m 以内に物・段差が無いことを確認する。台の上では行わない。
- **Bittle は床に置いたまま、持ち上げない。** 脚が付いていないので、歩き方のトークンを送ってもその場から動かない（サーボだけが動く）。
- この実験は「`d` で止まらない」ことがありうる実験である。**問いに答えた後もサーボが動いていたら、すぐ電源を切る。** 切り方は準備の P-4 で確かめる（電池のボタンを長押しする）。それでも動いていたら、USB のケーブルも抜く。
- 道具（`e00-serial-probe`）は、終わるとき・エラーのとき・`Ctrl-C` を押したとき・ターミナルを閉じたときに `d` を送る。B-2〜B-4 で使う設定（`E00_ASK_AFTER_STOP_MS`）では、問いの前と、問いを見る 1.5 秒の後に、`d` を1回ずつ送る。B-1 では、問いを見る 1.5 秒の後に1回だけ送る。
- 次の表示が出たら、すぐ電源を切る。
  - `!! STOP TOKEN NOT SENT`（`d` を送れなかった）
  - `!! SECOND STOP TOKEN NOT SENT`（2回目の `d` を送れなかった。1回目は送った）
- **`Ctrl-Z` は使わない**（道具が一時停止し、`d` が送られないまま動き続ける）。止めるときは `Ctrl-C`。
- **`Ctrl-S` は押さない**。ターミナルの表示が止まる。止まったら、まず `Ctrl-C` を押し、それから `Ctrl-Q` で表示を戻す。
- 起動時に `no independent stop path, refusing to run` と表示されたら、道具は `d` だけを送って終わる。その回は実施できなかったとして記録する。

## 準備

コマンドは、リポジトリのルート（`Cargo.toml` がある場所）で実行する。各手順の出力は `E00_LOG=<ファイル>` で `experimentals/raw/` に保存する（このフォルダの中身はコミットされない。`tee` は使わない）。道具は同じ名前のファイルを上書きするので、やり直すときは名前の末尾に `-r2`・`-r3` のように番号を付け、前の回のファイルを残す。

- P-0. Rust を使えるようにする。E00 で用意した Mac なら、確かめるだけでよい。
  - 確かめ方: `cargo --version` を実行し、`cargo 1.` で始まる行が表示される。表示されなければ、[E00](E00-connectivity.md) の P-0 に従って入れる。
- P-1. Arduino IDE を終了する（IDE ごと）。
  確かめ方: Dock の Arduino IDE のアイコンの下に点が無い。
- P-2. 道具をビルドする。
  ```sh
  git pull
  cargo build --release -p walk-experiments --bin e00-serial-probe
  ./target/release/e00-serial-probe 2>&1 | grep E00_ASK_AFTER_STOP_MS
  ```
  確かめ方: ビルドの最後に `Finished` と表示され、最後のコマンドで `E00_ASK_AFTER_STOP_MS` を含む行が表示される。表示されなければ、`git pull` からやり直す。
- P-3. 電池を充電し、Bittle に付ける。USB アダプタで Mac とつなぎ、Bittle の電源を入れる。
  確かめ方: P-6 の出力に起動の表示（`* Start *`）が出る。
- P-4. 電源の切り方を確かめる。電池のボタンを長押しすると電源が切れる（E00 の実施のとき、実施者が電池の確認でボタンを長押しして切れた）。
  1. 電池のボタンの位置を確かめる。
  2. 長押しして電源を切り、もう一度入れる。
  確かめ方: 入れ直した後の P-6 が通る。USB をつないだままでも、電池を切ればサーボは止まる見込み（推論。**未確認**）なので、止まらないときは USB も抜く、と覚えておく。
- P-5. 置き方を決める。Mac は、画面から目を移すだけで Bittle の前脚付近（首の後ろの肩のあたり）が見え、電池のボタンにすぐ手が届く位置に置く。
  確かめ方: 画面を見た姿勢のまま、目だけを動かして前脚付近のサーボが見え、手を伸ばせばボタンに届く。
- P-6. ポートを調べ、起動を待つ時間を設定し、起動と電池を確かめる。**ポート名は結果に貼らない。**
  ```sh
  ./target/release/e00-serial-probe --list
  export E00_SETTLE_MS=8000
  echo "$E00_SETTLE_MS"
  E00_LOG=experimentals/raw/e13-p6.txt ./target/release/e00-serial-probe <PORT> kbalance
  ```
  確かめ方: `--list` に `usbserial` を含む `/dev/cu.` の行がある（それを `<PORT>` に使う）。`echo` で `8000` と表示される。最後の出力で、`* Start *` を含む `<-` の行が1つだけ、`Ready!` の行が最初の `->` より前、`Low power` の行が無い。
  - `* Start *` が2つ以上あるか、`Low power` が出たら、電池を充電してから P-6 をやり直す。
  - ターミナルを開き直したときは、`export` と `echo` からやり直す（`export` はそのターミナルの中だけで有効。既定の 2000 に戻ると、起動の途中で送ってしまう。F-B9）。

## 手順

### 共通の決まり

- 出力に、最初の `->` より前に `* Start *` を含む行が2つ以上ある回（起動の途中で再起動した。F-B15）と、`Low power` の行がある回は使わない。電池を充電し、P-6 を通してから、その回をやり直す。最初の `->` より後に `* Start *` が出た回は、B-4 では捨てずに記録する（B-4 の節）。ほかの手順では使わず、やり直す。
- 答えが `answer: none`・`answer: interrupted` の回、`answer:` の行が無い回は使わず、やり直す。
- 人が見る理由: 止まったかどうかは、ファームの出力からは分からない。E00 では、`d` に対して `\n\r\n` のような短い応答しか返っていない（E00 の結果の節）。F-B11 の `k` のような、動作が終わったしるしは無い。
- `E00_ASK_AFTER_STOP_MS` を使う B-2〜B-4 は、実機では**未実行**（偽のシリアルポートのテストでだけ動作を確かめた）。問いが出ない、`d` の前に問いが出るなど、道具がおかしいときはその回を使わず、「記録すること」の最後の項目に書く。

### 問いの答え方（どの手順も同じ）

1. コマンドを実行したら、画面を見て待つ（Bittle を見ている必要はない）。
2. `>>> LOOK NOW:` が表示されたら、目を Bittle の前脚付近のサーボへ移す。
3. `>>> answer y (yes), n (no) or ? (could not tell), then press Enter:` が表示されたら、`y`（動いている）・`n`（止まっている）・`?`（分からない）のどれかを入力して Enter を押す。
4. 答えた後もサーボが動いていたら、すぐ電源を切る（その回の結果はそのまま記録する）。

### B-1. 対照: `d` を送らなければ、まだ動いているか

`kwkF` を送り、`d` を送る前に問う。B-2 で「止まった」と答えたときに、それが `d` のおかげか、もともと止まる時刻だったのかを見分けるため。

`kwkF` は、もともと数秒で止まる見込みがある（F-B14: 1回送っただけで、5 秒後には止まっていた。F-B11: `kwkF` の `k` は約 0.4 秒で返った）。そこで、1 秒後と 3 秒後の2つの時刻で確かめる。

B-1a. 1 秒後（2回）:

```sh
E00_FINAL_WAIT_MS=1000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1a-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=1000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1a-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

B-1b. 3 秒後（2回）。B-1a が2回とも `answer: yes` のときだけ行う:

```sh
E00_FINAL_WAIT_MS=3000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1b-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=3000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b1b-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

1つずつ実行し、終わってから次を実行する（それぞれ約 15 秒）。

### B-2. `d` の後に止まっているか

B-1 の結果で、次のどちらか一方を行う（2回）。どちらにも当てはまらないときは B-2・B-3 を行わず、B-4 へ進む。

- B-2A（B-1b が2回とも `answer: yes`）: `kwkF` の 1 秒後に `d` を送り、その 2 秒後（`kwkF` から 3 秒後。B-1b と同じ時刻）に問う。
  ```sh
  E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-1.txt ./target/release/e00-serial-probe <PORT> kwkF
  E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-2.txt ./target/release/e00-serial-probe <PORT> kwkF
  ```
- B-2B（B-1a が2回とも `answer: yes` で、B-2A の条件に当てはまらないとき）: `kwkF` の 0.2 秒後に `d` を送り、その 0.8 秒後（`kwkF` から 1 秒後。B-1a と同じ時刻）に問う。
  ```sh
  E00_FINAL_WAIT_MS=200 E00_ASK_AFTER_STOP_MS=800 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-1.txt ./target/release/e00-serial-probe <PORT> kwkF
  E00_FINAL_WAIT_MS=200 E00_ASK_AFTER_STOP_MS=800 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b2-2.txt ./target/release/e00-serial-probe <PORT> kwkF
  ```

### B-3. `d` の 0.5 秒後に止まっているか

B-2A を行い、2回とも `answer: no` だったときだけ行う（2回）。

```sh
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=500 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b3-1.txt ./target/release/e00-serial-probe <PORT> kwkF
E00_FINAL_WAIT_MS=1000 E00_ASK_AFTER_STOP_MS=500 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b3-2.txt ./target/release/e00-serial-probe <PORT> kwkF
```

- 問いが出てから目を移すまでに時間がかかるので、実際に見ているのは `d` の 0.5 秒より後になる。「0.5 秒＋目を移す時間」の後の様子として扱う。
- `d` を受けたとき、休む姿勢へ動いてからサーボを切る見込みがある（推論。**未確認**）。そのため B-3 の `yes` は、歩行が続いていたのではなく `d` 自身の動きかもしれない。B-3 の結果は、その動きを含めた「止まるまでの遅れ」として扱う。

### B-4. `d` を2回続けて送る

B-1 の結果にかかわらず行う（出力の判定は対照に関係しないため）。`kwkF` の 1 秒後に `d` をトークンとして送り、その 0.2 秒後に道具がもう一度 `d` を送る。その 2 秒後に問う。1回行う。

```sh
E00_WAIT_MS=1000 E00_FINAL_WAIT_MS=200 E00_ASK_AFTER_STOP_MS=2000 E00_ASK='前脚付近のサーボは、今動いていますか？' E00_LOG=experimentals/raw/e13-b4.txt ./target/release/e00-serial-probe <PORT> kwkF d
```

- 出力では、続けて送った2つの `d`（ログの最初の2つの `-> "d"` の行）のそれぞれに何が返るかを見る。問いの後に、道具が3つ目の `d` を送る。
- 最初の `->` より後に `* Start *` が出たら（`d` を重ねて送った後の再起動かもしれない）、その回を捨てずに記録する。P-6 を通してから1回だけやり直し（ファイル名に `-r2`）、その結果も記録する。

#### 気づいたこと

- B-1 の対照は、答える時点が `d` の後になる組み方だった。道具は問いの約 1.5 秒後に `d` を送り、答えを促す表示はその後に出る（出力の `-> "d"` と `>>> answer` の順）。B-1a-1 の `n` も B-1a-2 の `y` も、`d` の後に入力された。
- B-1a-2 で、問いが出た時点（`kwkF` の約 1 秒後）では動いていて、答えるまでの間に止まったのなら、止まったのが `kwkF` が自分で止まったからなのか、約 2.5 秒後に送った `d` によるのかは、見分けられない（**未確認**）。1回目は `n` と答えた（入力は問いの約 4 秒後、`d` の約 2.5 秒後）。F-B14 では、`kwkF` を1回送っただけで 5 秒後には止まっていた。
- `kwkF` の `k` は、送ってから約 0.37 秒で返った（2回とも。F-B11 と同じ傾向）。B-1a-2 では、その後の問いの時点でも動いていたと答えている（1回、答えは「ようだ」）。`k` は、歩き方では「受け付けた」しるしで、動作の終わりではないと読める（06 2.1節の推論と合う。**未確認**）。`k` が動作の終わりを表すかは、どの動作についても確かめていない。
