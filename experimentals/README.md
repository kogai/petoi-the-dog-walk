# 実験

実機・API キー・人の目が要る確認を、人に依頼するための手順書と、その結果の記録を置く。
依頼の流れは [git-workflow.md](../docs/rules/git-workflow.md) 4節。**実験1つにつき1つの PR** で依頼する。
実験の ID と、それぞれが何の設計を待っているかは [07-roadmap.md](../docs/design/07-roadmap.md) の「実験の一覧」にある。

状態は **未依頼 → 依頼中 → 実施済み → 反映済み** の順に進む。

どの実験をいつ依頼するかは、[07-roadmap.md](../docs/design/07-roadmap.md) のフェーズと「待っている設計」で決める。

## 手順書の書き方

- [TEMPLATE.md](TEMPLATE.md) から作る。
- 人が一人で、コピー＆ペーストだけで進められるように書く。プレースホルダーは `<PORT>`、`<IP>` のように示す。
- 実行していないコマンドやプログラムには **未実行**、確かめていないトークンや API 名には **未確認** と書く（TEMPLATE の手順の例を参照）。
- 判定基準は、起こりうる結果ごとに、設計のどこがどう変わるかを書く。
- 実機を動かす手順には、止め方を必ず書く。
- 実験で使う道具は Rust で書き、ワークスペースの `walk-experiments` クレートに置く（検査・レビューの対象にするため）。

## 共通の注意（実施する人へ）

- 実機を動かすときは、Bittle を平らな床に置き、周囲 2m 以内に物・段差が無い場所で行う。台の上では行わない。
- 動作がおかしいときは、**電源を切る**。これが確実な止め方。
  停止トークン `d` でも止まる見込みだが、シリアルでどう働くかはまだ確かめていない（E00 で確かめる）。`d` の送り方は各手順書の「安全上の注意」に書く。
- **このリポジトリは公開されている。** 結果を貼る前に、API キー・IP アドレス・シリアルポート名・PC 名・ユーザー名・ホームのパス・機器のシリアル番号を `<IP>`、`<PORT>` のように伏せる（[public-repo.md](../docs/rules/public-repo.md)）。エラーの表示にはホームのパスやポート名が入りやすい。
- 生の出力は `experimentals/raw/` に保存する。このフォルダの中身はコミットされない（フォルダ自体は `.gitkeep` でリポジトリにある）。
- API キーは環境変数で渡し、ファイルや結果に書かない。使った後は、結果に含まれていないことを [public-repo.md](../docs/rules/public-repo.md) 3節の方法で確かめる。
- 写真や動画を載せるときは、部屋の様子や人が写っていないか確かめる。
- 実行したコマンドと、出力をそのまま（伏せた上で）貼る。要約だけにしない。
- 結果を PR のコメントに貼ってもよい。その場合は、エージェントが手順書の「結果」節に転記する。
