- 依頼日: 2026-10-26

## 目的

脚を付けた Bittle で、歩き方のトークン `kwkF` について次の3つを確かめる。

1. `kwkF` を1回送っただけで、歩く動きはいつまで続くか（A）。
2. `kwkF` を一定の間隔で送り直したとき、送り直した直後も歩く動きをしているか（B）。
3. 歩いている途中で停止トークン `d` を送ると、歩く動きが止まるか（C）。

結果で決まること:

- 歩き方を送り直す間隔の仮の値と、送り直してよいか（[06-transport.md](../docs/design/06-transport.md) 2節。今は「一定の間隔で送り直す」とし、間隔は**未確認**）。
- `d` で歩き方を止められるか（06 2節、[ADR-0001](../docs/design/adr/0001-driver-layer.md) 2.6節 S1）。フェーズ 1c（[07](../docs/design/07-roadmap.md)）の前提の一部。長い動作（`khi`）の打ち切りは E13 で確かめる。

### 人に見てもらう理由と、判定に使う事実・推論

- 事実: `kwkF` を送ると、約 375 ms で `k` が返る（F-B11。脚なし）。
- 事実: 脚なしで `kwkF` を1回送ると、5 秒後には前脚付近のサーボは動いていなかった（F-B14。人が見て答えた。1回のみ）。
- 推論（06 2.1節。E13 の 2026-10-16 の記録とも合う）: 歩き方の `k` は「受け付けた」しるしで、歩く動きの終わりではない。そのため、歩いているかは道具の出力から分からない。
- そこで、歩いているかだけは人に見てもらう。問いは1回の実行につき1つで、道具が決まった時刻に出す（[README](README.md) の「人が実行できる手順にする」）。問いは、そのときの状態だけを聞く。
- `d` への応答（停止の処理が走ったか）は、道具の出力で見る（判定基準の「停止の応答」）。

この実験では確かめないこと:

- 歩く速さ・進んだ距離・止まるまでのミリ秒単位の遅れ（E09 で測る。[08](../docs/design/08-navigation.md) 5.1節）。
- 送り直したときに、問いの時刻以外で歩きが一瞬途切れるか。人が動きを覚えておかないと答えられないため（README のルール）。B で分かるのは、送り直した直後の1つの時刻に歩く動きをしているかだけ。
- `kwkF` 以外の歩き方。Wi-Fi 経路（E15）。
- 長い動作（`khi`）を `d` で打ち切れるか（E13）。

## 必要なもの

- 人数と役目: **2人**。
  - 画面の人: キーボードと画面を担当する。コマンドを実行し、`>>> LOOK NOW` が出たら声で「今」と言い、Bittle の人の答えを入力する。Bittle は見なくてよい。
  - Bittle の人: Bittle だけを見る。「今」と言われた時点の様子を、「はい」「いいえ」「分からない」のどれかで答える。危ないときは電源を切る（安全上の注意）。画面は見なくてよい。
  - 1人では行わない（歩いている Bittle から目を離して画面を見ることになるため）。
- 機材: Bittle（標準ファーム。**脚を付けた状態**。脚の組み付けとキャリブレーションは 2026-10-26 にオーナーが済ませたと報告した。エージェントは確かめていない）、USB アダプタと USB ケーブル、充電した電池、Mac
- 場所: 平らな床。Bittle の前に 2m 以上、横と後ろに 1m 以上、物・段差が無い場所（共通の注意の 2m を、歩く向きに取る）。床は滑りにくいもの（材質を記録する）。
- ソフトウェア: mise と Rust（準備の P-0）、このリポジトリ（道具 `e00-serial-probe`）
- 所要時間の目安: 60分（12回の実行と、そのたびの置き直し）

## 安全上の注意

- **確実な止め方は、電池のボタンを長押しして電源を切ること**（準備の P-4 で、2人とも位置を確かめる）。それでも動いていたら、USB のケーブルも抜く。
- Bittle は歩いて前へ進む。1回の実行で歩く時間は最長で約 7 秒（A-3。止まらなかった場合）。歩く速さは測っていない（**未確認**）。
- 次のどれかになったら、Bittle の人がすぐ電源を切る。答えより先にする（その回は使わない）。
  - Bittle が、物・段差・床の端・人の足に近づいた。
  - USB のケーブルが張りそうになった、または Bittle がケーブルを踏んだ・引きずった。
  - 倒れた、脚がおかしな向きに動いた、異音がした。
- ケーブルは、Bittle の後ろから Mac まで、たるませて床に置く。Bittle の前にケーブルを置かない。Mac は Bittle の後ろ側に置く。
- 歩いている Bittle を手で持ち上げない、脚に手を近づけない（サーボに指を挟む見込み。推論）。止めるのは電源で行う。
- 道具（`e00-serial-probe`）は、終わるとき・エラーのとき・`Ctrl-C` を押したとき・ターミナルを閉じたときに `d` を送る。画面の人は、Bittle の人に「止めて」と言われたら `Ctrl-C` を押す（Bittle の人は、それを待たずに電源を切ってよい）。
- `!! STOP TOKEN NOT SENT` と表示されたら、画面の人が声で伝え、Bittle の人がすぐ電源を切る。
- **`Ctrl-Z` は使わない**（道具が一時停止し、`d` が送られないまま動き続ける）。止めるときは `Ctrl-C`。
- **`Ctrl-S` は押さない**。ターミナルの表示が止まる。止まったら、まず `Ctrl-C` を押し、それから `Ctrl-Q` で表示を戻す。
- 起動時に `no independent stop path, refusing to run` と表示されたら、道具は `d` だけを送って終わる。その回は実施できなかったとして記録する。
- ポートを開くと起動の表示が出て、その間にサーボが動くことがある（F-B9）。実行の前に、Bittle の人は Bittle から手を離して「いい」と言う。画面の人は、それを聞いてから実行する。
- 実行と実行の間に Bittle を始めの位置に戻すのは、道具が終わってから。Bittle の人が、休む姿勢になったのを見てから持つ。

- P-1. Arduino IDE を終了する（IDE ごと）。
  確かめ方: Dock の Arduino IDE のアイコンの下に点が無い。
- P-2. 道具をビルドする。
  ```sh

  cargo build --release -p walk-experiments --bin e00-serial-probe
  git merge-base --is-ancestor 759e5d7 HEAD && echo stop-fixed
  git rev-parse --short HEAD
  ```

  確かめ方: ビルドの最後に `Finished` と表示される。`stop-fixed` と表示される（停止を `d\n` だけで送る道具になっている。#27）。表示されなければ、`git pull` からやり直す。最後のコマンドで表示された短いハッシュを、結果の「このリポジトリのコミット」に書く。
- P-3. 場所を整える。Bittle を床に置き、頭を、物の無い 2m 以上ある向きに向ける。USB のケーブルを Bittle の後ろから Mac までたるませて置く。
  確かめ方: Bittle の人が、Bittle の前 2m・横と後ろ 1m に物・段差・ケーブルが無いことを見て、「いい」と言う。この位置を「始めの位置」とする（床にテープで印を付けてよい）。
- P-4. 電源の切り方を確かめる。2人とも電池のボタンの位置を確かめ、Bittle の人が長押しして電源を切り、もう一度入れる。
  確かめ方: 入れ直した後の P-5 が通る。
- P-5. 電池を充電して付け、USB アダプタで Mac とつなぎ、電源を入れる。ポートを調べ、起動を待つ時間を設定し、起動と電池を確かめる。**ポート名は結果に貼らない。** `kbalance` で Bittle は立ち上がる見込み（推論）。
  ```sh
  ./target/release/e00-serial-probe --list
  export E00_SETTLE_MS=8000
  echo "$E00_SETTLE_MS"
  E00_LOG=experimentals/raw/e14-p5.txt ./target/release/e00-serial-probe <PORT> kbalance
  ```
  続けて、起動と電池を数える（受け取った塊をつないで数える。理由は「共通の決まり」）:
  ```sh
  L=experimentals/raw/e14-p5.txt
  sed -n 's/^ *[0-9.]* ms  <- "\(.*\)"$/\1/p' "$L" | tr -d '\n' | grep -o -F '* Start *' | wc -l
  sed -n 's/^ *[0-9.]* ms  <- "\(.*\)"$/\1/p' "$L" | tr -d '\n' | grep -o -F 'Low power' | wc -l
  ```

  - ターミナルを開き直したときは、`export` と `echo` からやり直す（`export` はそのターミナルの中だけで有効）。
- P-6. 問いを入れる。どの回も同じ問いを使う。

## 手順

### 共通の決まり

- 1回ごとに、次の順で進める。
  1. Bittle の人が、Bittle を始めの位置に置き、手を離して「いい」と言う。
  2. 画面の人がコマンドを実行する。Bittle の人は Bittle だけを見る。
  3. 画面に `>>> LOOK NOW` が出てベルが鳴ったら、画面の人が「今」と言う。
  4. Bittle の人は、「今」と言われた時点の様子を、すぐ「はい」「いいえ」「分からない」で答える。その後の様子で答えを変えない。
  5. 画面に `>>> answer` が出たら、画面の人が、はい → `y`、いいえ → `n`、分からない → `?` を入力して Enter を押す。
  6. 道具が終わってから、次の回に進む。
- 道具は改行ごとではなく、受け取った塊ごとに `<-` の行を出す。下の確かめは、`<-` の中身を受け取った順につないだものに対して行う（P-5 の数えるコマンドと同じ）。時刻を測ったり数えたりするのは、エージェントが行う。実施する人は、出力を貼るだけでよい。
- 次のどれかに当たる回は使わない。当たるかはエージェントが確かめ、当たったら、電池の充電と P-5 からのやり直しを依頼する。
  - つないだ中身に `* Start *` が2つ以上ある回（途中で再起動した。F-B15）
  - `Ready!\r\n` が、最初の `->` より前に届いていない回（F-B9）
  - つないだ中身に `Low power` がある回
  - `read error:` で始まる行がある回
  - 安全上の注意に従って電源を切った回
  - `answer:` の行が `yes`・`no`・`unknown` のどれでもない回（`answer: none`、`answer: interrupted`、`answer:` の行が無い）。その回はやり直す
- 「`k` の時刻」は、`kwkF` の `->` の時刻から、その後の `<-` の中身をつないで最初に現れる `k\r\n` の、`\n` を含む `<-` の行の時刻まで（E00 と同じ）。起動の表示の先頭の `k`（最初の `->` より前）は数えない。

## 判定基準

使った回だけで判定する。各段の判定は、前の段が成り立ったときだけ行う。

- 「はい」「いいえ」は、その回の `answer: yes`・`answer: no`。`answer: unknown` は「分からない」。
- 「停止の応答」は、C で道具が最初に送った `d` の `->` から 1 秒以内で、かつ次の `->`（2つ目の `d`）より前に届いた中身をつないだものに、`d\r\n` があり、`?` が無いもの（ソースの読みでは `g\r\nd\r\n` を返す見込み。推論。E13 と同じ定義）。
- 「送り直しの応答」は、B の各 `kwkF` の `->` から次の `->` までにつないだ中身に、`k\r\n` があり、`?` が無いこと。

| 観察 | 結果 | 設計への影響 |
|---|---|---|
| 対照（A-1） | 2回とも「はい」 | 対照が成り立つ（`kwkF` で、脚付きで歩き始める）。A-2 以降を判定する |
| 対照（A-1） | 「いいえ」か「分からない」の回がある | 分からなかった（歩き始めたかを確かめられない）。A-2 以降は判定しない。保留。06 2節の送り直しの間隔も、`d` で歩き方を止められるかも決めず、フェーズ 1c に進まない。出力とキャリブレーションの状態を調べてから再依頼する |
| 1回で続く時間（A-2・A-3） | A-2・A-3 の4回とも「はい」 | `kwkF` 1回で 5 秒より長く歩く見込み（脚付き。F-B14 の脚なしの結果とは違う）。送り直しは歩き続けるためには要らない見込みだが、06 2節の「送り直す」はやめずに、間隔は B で「はい」だった最長の間隔（B-2 なら 2 秒）を仮の値にする。止めるのは `d` だけになるので、C の結果がいっそう重い |
| 1回で続く時間（A-2・A-3） | A-2 は2回とも「はい」、A-3 は2回とも「いいえ」 | 1回で 2.5〜5 秒（問いの 1.5 秒の見る時間を足すと、7 秒までの間）で止まる見込み。送り直しの間隔の仮の値は 2 秒（B-2 が成り立てば）。B-2 が成り立たなければ、B-1 の 1 秒 |
| 1回で続く時間（A-2・A-3） | A-2 が2回とも「いいえ」 | 1回で 2.5 秒より前に止まる見込み。送り直しの間隔の仮の値は 1 秒（B-1 が成り立てば）。B-2 は判定に使わない（2 秒の間に止まる見込みのため） |
