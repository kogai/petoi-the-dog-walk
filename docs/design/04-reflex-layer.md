# 04. 反射層（ハエ脳）

フェーズ3で足す。フェーズ1・2では `NullReflex`（常に「何もしない」を返す）を使う（G4）。

## 1. 役割（設計案）

100ms ごとに速い反応を出す。判断の中心ではない。

## 2. 出力の対応（設計案）

ハエ脳の出力は7種類（F-F8）。

| ハエの動き（運動ニューロン群） | Bittle |
|---|---|
| stand（どの群も閾値未満） | `kbalance`（または `kup`） |
| walk_forward（fwd） | `kwkF` |
| walk_backward（back） | `kbk` |
| jump_away（jump） | 対応スキル未確認（代替案: `kbk` か `krnF`）→ D-07 |
| punch（punch）/ kick（kick）/ block（wing） | 対応する動作が確認できていない → D-07 |

## 3. 感覚入力（未確認）

公式実装の感覚入力はゲーム状態から作られている（F-F4）。Bittle で何を入力にするかは、
E01（IMU）・E02（カメラ）の結果で選べる範囲が決まる（D-02）。

## 4. 性格づけ（設計案）

Jev の答え（Score や Noul）を、群ごとの閾値・ゲイン（F-F3）の倍率にコード側で変換する。
例: 臆病さが高いと、後退・逃避の閾値を下げる。
変換は純粋関数にして単体テストする。実機で違いが見えるかは E08。

## 5. 実行方法（未決定 D-06）

公式実装のシミュレーションはブラウザの JavaScript で動き、`server.py` は配信・Jev の中継・記録だけを行う（F-F1、F-F9）。
そのため `server.py` をそのまま Python から呼んでも、シミュレーションは使えない。選択肢:

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A | Node.js で JS をそのまま動かし、標準入出力か WebSocket で Python とつなぐ | 公式と同じ挙動 | プロセスが2つ。遅延が増える |
| B | Python（numpy）へ移植 | 1プロセス。テストしやすい | 移植の正しさの検証が必要 |
| C | ブラウザで動かし、WebSocket で Python とつなぐ | 可視化がそのまま使える | 自動テストが難しい |

どの案でも `Reflex` Protocol の後ろに隠すので、他のモジュールには影響しない。
