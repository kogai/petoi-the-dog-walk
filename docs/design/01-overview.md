# 01. 概要

初代 Petoi Bittle（NyBoard）を Mac から無線で動かす。
「理性的反応」を TypeSafe の Jev、「本能的反射」を maleCNS コネクトームのハエ脳シミュレーションが担当する。

## 1. ゴール（設計案）

- G1: 非エンジニアが書いた自由文の「性格」と「スキル」を読ませて、Bittle の振る舞いを決める。
- G2: 自由文による「その場の指示」を、他の判断より優先する。
- G3: 速い反応が必要な場面は、ハエ脳の反射層に任せる。
- G4: ハエ脳は判断の中心ではない。無くても成立する構成にする。

## 2. やらないこと（設計案）

- Bittle 側ファームウェアへのシミュレーション搭載（ATmega328P に載らない。[facts.md](facts.md) F-B1）。
- Jev に文章を生成させること（Jev は生成しない。F-J1）。
- Jev に優先順位の判定を任せること（コード側で行う。[05-arbitration.md](05-arbitration.md)）。
- カメラの深掘り（方針として後回し）。

## 3. 制約

| ID | 制約 | 根拠 |
|---|---|---|
| C1 | Bittle の MCU は SRAM 2KB。判断はすべて Mac 側 | 確認済み F-B1 |
| C2 | Bittle への指示は文字列トークン | 確認済み F-B4, F-B5 |
| C3 | Jev の呼び出しは cookbook の例で 0.09〜0.31 秒。100ms 周期に毎回は間に合わない見込み | 数値は確認済み F-J6。見込みは推論 |
| C4 | Jev は日本語で精度が下がる | 確認済み F-J8。影響の大きさは実験 E05 |
| C5 | Jev は数の計算・日付比較が苦手 | 確認済み F-J8。数値はコード側で処理する |
| C6 | ハエ脳のシミュレーションはブラウザ（Web Worker、JavaScript）で動く | 確認済み F-F1、F-F9。Python からの使い方は未決定 D-06 |

## 4. 前提（検証しない）

  ただし、実装に必要な「応答の形式」は実験 E00 で記録してもらう。
