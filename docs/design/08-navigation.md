# 08. 場所の記憶と帰巣（検討中）

この文書は、今のロードマップ（[07](07-roadmap.md) のフェーズ0〜3）の**外**にある発展案をまとめる。
内容はすべて **設計案** か **未確認**。進めるかどうかは未決定（D-13）。
実験はここに計画として並べるだけで、依頼はしない。依頼するかどうかは D-13 で決める。

## 1. ゴール（設計案）

- N1: Bittle が、自分の目と記憶だけで「覚えた場所へ行く」「寝床に帰る」ができる。
- N2: 位置は、目的を果たせる程度に分かればよい。座標の正確さは目標にしない。
- N3: 経験を重ねるほど、迷う回数が減る（迷った場所の記憶を足していく）。

やらないこと（設計案）:

- 部屋の正確な地図（間取り）を作ること。カメラ1台で動きながら作る方法（単眼の Visual SLAM）は、脚の揺れ・低い視点（床から 10cm 前後、未計測）・模様の少ない床のために重い（推論）。
- 人が用意した地図に、ロボットの位置を合わせるだけの構成。この発展案の狙いは、Bittle が自分で場所を覚えることにあるため（設計案）。

## 2. 考え方（設計案）

位置を精度で決めるのではなく、**予測と確認を繰り返すループ**で、目的に足りる確からしさを保つ。

```
 予測: 歩いた分だけ、どの場所にいそうかをずらす（経路積分）
   ▼
 観測: 今の景色と、記憶した場所の景色を比べる
   ▼
 更新: どの場所にいそうかの見込み（場所ごとの確率）を直す
   ▼
 判断: 見込みが十分 → 目的の場所へ向かう
       見込みが不十分 → 確かめる動き（見回す、知っている場所へ戻る）
   ▼
 行動 ──▶ 予測へ戻る
 （迷った所では、次のために場所の記憶を足す）
```

- 記憶は、座標の地図ではなく、**場所（景色の記憶）と、場所どうしをつなぐ歩き方**のつながり（トポロジカルな記憶）にする。
- 知っている場所を見分けるたびに見込みが締め直されるので、経路積分の誤差は「次の見覚えのある場所まで」の分しか残らない、という見込み（未確認。E09・E11・E12 で確かめる）。
- 必要な精度は目的が決める。「寝床に帰る」なら、どの場所の近くにいるかと、次にどちらへ進むかが分かれば足り、最後は景色の照合で寝床を見分けて止まる。

### 2.1 層の分担（設計案）

| 部分 | 置き場所 | 中身 |
|---|---|---|
| 見込みの更新、確かめる動きを選ぶか、記憶の追加・統合 | `walk-core`（純粋関数） | 場所ごとの確率は数の計算なので、Jev に任せない（C5） |
| 景色の取得と縮小 | 殻（新しいクレート。名前・境界の trait は未定） | 画像を受け取り、低解像度のベクトルにして `walk-core` に渡す |
| 目的の解釈（「寝床に帰って」） | Jev | 記憶した場所の名前を Choice の選択肢にする |
| 迷ったときの振る舞い | Jev（性格） | 慎重なら知っている場所へ戻る、好奇心が強ければ見回す。どちらを選んでもループの不変条件（2.2）は守る |
| 障害物への反応 | ハエ脳（反射層） | ループの外側で速く反応する（[04](04-reflex-layer.md)） |

場所の名前は、新しい場所を覚えたときに人に尋ねて付ける案がある（「ここどこ？」→「キッチン」）。尋ね方は未定。

未定: ループが選ぶ動き（目的の場所へ向かう・確かめる動き）と、調停の規則（[05](05-arbitration.md)。指示 > 性格 > 反射 > 既定）との関係。`arbitrate` の入力や `Rule` を増やすことになるか、ループを Jev の選んだスキルの中で動かすかなど、D-13 で入れると決めたら決める。

### 2.2 不変条件（設計案。プロパティテストで検証する）

- V1: ループは必ず終わる。目的の場所に着くか、歩数・時間の上限を超えたら止まり、「迷子」として人に知らせる。
- V2: 場所ごとの確率は、更新の後も 0〜1 で、合計が 1。
- V3: 記憶の数には上限があり、超えたら似た記憶をまとめる。

### 2.3 評価の物差し（設計案）

位置の誤差ではなく、**目的を果たせた割合**と、**かかった時間（歩いた時間）**で測る。
シミュレーション（4節）と実機（E12）で同じ物差しを使う。

## 3. ハエ脳との関係

- 確認済み（F-F10）: 今のハエ脳の部分回路（約1.2万ニューロン）は、決まった感覚の群と運動の群のあいだを流れる影響の強さで、途中のニューロンを選んでいる。部位を指定して入れる処理は無い。
- 未確認: 選ばれた中に、中心複合体（楕円体など）のニューロンが入っているか。生成スクリプトと公開データから調べられる（実機は要らない）。
- 設計案: 入っていない場合でも、生成スクリプトには感覚の群を足す引数（`--probe-types`）がある（F-F10）。向きの回路を含む部分回路を作り直せば、経路積分の一部をハエ脳に担わせる案が考えられる。実現できるかは未確認で、D-06（ハエ脳の実行方法）が決まってから検討する。

## 4. 実機の前に行うこと（設計案。人に依頼しない）

偽の世界でループ全体を回す。実機も Jev の API キーも要らないので、このリポジトリの中で完結する。

- 偽の世界: 格子の部屋、壁、場所ごとの景色（ノイズを入れる）、歩いた量の誤差（E09 の結果が出るまでは仮の値）。
- テストの例: 「どこから始めても、誤差がこの範囲なら、上限の時間内に寝床に着くか、迷子として止まる」（V1）。
- E09・E10 の判定のしきい値（許せる経路積分の誤差、必要な視野）は、このシミュレーションで先に見積もり、手順書の判定基準に書く。
- 実験の結果（E09・E11）が出たら、偽の世界の誤差とノイズを、測った値に合わせる。

### 5.1 各実験の要点（設計案）

- **E09**: Mac は「歩数」を直接知らない。歩き方のトークンを受けた Bittle は歩き続ける見込みだが、未確認（E00 で確かめる）。そのため「何秒歩いたか」を入力にし、床に貼った目印と巻尺で、止まった位置と向きを測る。向きは IMU（E01 で読めれば）とも比べる。
  - 測定のために止めるのは停止トークン `d`。E00 で `d` が効かないと分かったとき、または E09 の最初に測る止まるまでの遅れが大きく揺れるときは、時間で区切る測り方ができないので、E09 は保留にする。異常があれば、いつでも電源を切る（その試行は記録から外す）。
  - 安全: 必要な広さは「（歩かせる最長の時間 ＋ E09 の最初に測る、`d` を送ってから止まるまでの遅れの上限）× E09 の最初に測る歩く速さ」に、周囲 2m（[experimentals/README.md](../../experimentals/README.md) の共通の注意）を足した範囲。その範囲に物・段差・ケーブルが無いことを確かめる。
  - 記録: 床の材質、電池の残量、載せている物。カメラを載せると歩き方が変わる見込み（推論）なので、E10 でカメラが決まったら、載せた状態で一部を測り直す。
- **E10**: 視野が狭いと向きの手がかりが減る見込み（未確認。E10 と 4節のシミュレーションで確かめる）。視野の広さを優先して選ぶ。
- **E11**: 画像は部屋の写真なので、**コミットしない**（[public-repo.md](../rules/public-repo.md)）。`experimentals/raw/` に置き、人が手元で解析の道具（`walk-experiments` に置く。未作成）を動かし、数値の結果だけを記録する。
  - 解析の道具は、場所と撮り方のラベル（「場所A・回転30°」など）だけを出力し、ファイル名やパスを出さない。
  - 写真に人が写らないようにする。写真の位置情報（EXIF）にも注意する。結果の PR には、例示用も含めて画像を貼らない。
- **E12**: 成功の割合は、1回ではなく複数回（回数は手順書で決める）の試行で数える。
  - N3 を確かめるため、同じ開始の条件で、迷った場所の記憶を足す前と後の試行を比べ、迷子として止まった回数と、着くまでの時間の変化を記録する。止め方（V1 の上限と、電源を切ること）を手順書に必ず書く。
  - 安全: 家具のある部屋を歩くこと自体が目的なので、共通の注意（周囲 2m 以内に物・段差が無い）を満たせない。E12 では代わりに、歩ける範囲を囲う（段差・階段・玄関をふさぐ）、壊れやすい物とケーブルを片付ける、ペットを部屋の外に出す、人が常に手の届く距離で付き添い、すぐ電源を切れるようにする、を条件にする（設計案）。反射層（障害物への反応）がまだ無い場合は、そのことも手順書に書く。
  - 共通の注意に「手順書で別に定める場合はそれに従う」と足すかどうかは、E12 の依頼の PR で決める。
