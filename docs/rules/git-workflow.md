# Git の運用

## 1. ブランチ

- `main` に直接コミットしない。
- ブランチ名: `<種類>/<短い説明>`（例: `feat/arbiter`、`docs/transport`、`exp/e00-connectivity`）。
  エージェントのセッションで名前が指定されている場合は、それに従う。

## 2. コミット

- 1コミット1つの目的。件名は英語の命令形で 72 文字以内（例: `Add arbiter with priority rules`）。
- 本文に「なぜ」を書く。関係する設計 ID（D-03 など）や実験 ID（E00 など）があれば書く。
- コミットの前に `scripts/check.sh` を通す。

## 3. PR

- 本文は `.github/pull_request_template.md` に沿って書く。
- CI が赤い PR はレビューを依頼しない。
- 設計を変える PR と実装の PR は、できれば分ける。

## 4. 実験依頼の流れ

実機・API キー・人の目が要る確認は、エージェントが実行しない。次の流れで人に依頼する。

1. エージェントが `experimentals/E<番号>-<名前>.md` を [テンプレート](../../experimentals/TEMPLATE.md) から作り、PR を出す。
   PR のタイトルは `[実験依頼] E<番号> <名前>`。
2. 人が手順どおりに実験し、同じファイルの「結果」節を埋めてコミットする（またはコメントで結果を貼る）。
3. エージェントが結果を読み、`docs/design/`（`facts.md` の事実、`decisions.md` の決定）へ反映する。
   反映は別の PR でもよい。
4. 人がマージする。

実験結果は、記録されるまで「未確認」のまま扱う。
