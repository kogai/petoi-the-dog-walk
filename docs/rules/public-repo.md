# 公開リポジトリでの注意

このリポジトリは公開されている。コミットした内容は、あとで消しても履歴・フォーク・キャッシュに残る前提で扱う。

## 1. コミットしてはいけないもの

| 種類 | 例 |
|---|---|
| 秘密情報 | API キー、トークン、パスワード、`.env` |
| ローカル環境の状況 | ホームディレクトリのパス（`/Users/<名前>/`、`/home/<名前>/`）、PC 名・ユーザー名、シリアルポート名（`/dev/cu.<機器名>`）、ローカルの設定ファイル（`.claude/settings.local.json` など） |
| ネットワークの情報 | IP アドレス（プライベートも含む）、Wi-Fi の SSID、MAC アドレス |
| 機器・個人の識別情報 | シリアル番号、Bluetooth の機器名、メールアドレス、写真・動画に写った部屋や人 |
| 実験の生データ | 上のどれかを含むログ。貼る前に伏せる |

伏せるときは `<IP>`、`<PORT>`、`<HOME>` のようにプレースホルダーに置き換える。

## 2. 仕組みで防ぐ

- `.gitignore` でローカルのファイル（`.env`、`*.local.*` など）を除外している。実験の生の出力は `experimentals/raw/` に置けばコミットされない。
- `scripts/check-public.sh` が、次の形の文字列を探し、見つかれば失敗する。
  - ホームのパス（macOS・Linux の `/Users/…`・`/home/…`、Windows のユーザーフォルダ）
  - シリアルポート名（macOS の `/dev/cu.…`・`/dev/tty.…`、Linux の `/dev/ttyUSB…`・`/dev/ttyACM…`）
  - プライベート IPv4 アドレス（10.x、172.16〜31.x、192.168.x）
  - MAC アドレス
  - メールアドレス（コミットの署名に使う noreply のアドレスなどは除く）
  - 一部の API キーの形（`sk-…`、`ts-…`、GitHub・AWS のトークン）
- 検査の対象は3つ。CI は PR ごとに 1 と 3 を実行する（`.github/workflows/public-check.yml`）。
  1. `scripts/check-public.sh`: 作業ツリーのファイル（追跡中と、無視されていない新しいファイル）
  2. `scripts/check-public.sh --staged`: ステージした追加行。コミットの前に手元で実行する
  3. `scripts/check-public.sh --range A..B`: その範囲のコミットで追加された行と、コミットメッセージ。途中のコミットで入れて後で消したものも見つける
- **見つけられるのは一部だけ。** グローバル IP、PC 名、Bluetooth の機器名、ループバック（127.x）、形の違う API キー、PR の本文やコメントは見つけられない。人の目での確認（3節）が本体。
- 検査が壊れた（正規表現の誤りなど）ときは「ok」ではなく失敗する。
- macOS 標準の bash 3.2 と BSD の grep・sed で動くように書いているが、macOS 上での動作はまだ確かめていない。CI（Linux）の結果を正とする。
- 誤検知を許可するときは、その行の中身に `public-ok` と書き、PR で理由を説明する。

## 3. コミットの前に

- `git diff --staged` を読んで、上の表に当てはまるものが無いことを確かめ、`scripts/check-public.sh --staged` を通す。`git add -A` の前に `git status` で対象を確認する。
- 実験結果を貼るときは、出力を1行ずつ確認して伏せてからコミットする。エラーの表示（スタックトレースなど）にはホームのパスやポート名が入りやすい。
- API キーを使った後は、結果に含まれていないことを確かめる。`: "${TYPESAFE_API_KEY:?}" && grep -cF "$TYPESAFE_API_KEY" <ファイル>` の出力（件数）が `0` であればよい（1行目で、変数が空でないことを確かめている）。
- 入れてしまったら、push する前なら `git commit --amend` などで取り除く。push した後なら、すぐに人に知らせる（秘密情報は無効化が先。履歴を消すだけでは足りない）。
