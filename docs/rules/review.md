# レビュー

## 1. 流れ

```
実装 → scripts/check.sh → サブエージェントレビュー（必須のもの）→ 指摘に対応 → PR → 人のレビュー → 人がマージ
```

- エージェントは PR をマージしない。マージは人が行う。
- サブエージェントの指摘には、すべて「直した」か「直さない理由」を PR 本文の「レビュー対応」に書く。

## 2. サブエージェント

定義は `.claude/agents/` にある。レビュー役は読み取り専用で、コードを書き換えない。

| エージェント | 見るもの | 必須になる変更 |
|---|---|---|
| `code-reviewer` | 正しさ、型、テストの有無と質、純粋な核と殻の分け方、境界の守り方 | Rust のコード（`crates/`）か、ハーネスの設定を変えたとき |
| `design-reviewer` | 設計書との食い違い、事実と設計案の書き分け、決定事項の記録漏れ | `docs/` を変えたとき、または クレートの構成や境界の trait・型を変えたとき |
| `safety-reviewer` | 実機を動かす経路: 停止トークンの送信、非常停止、送信の許可リスト、タイムアウト、秘密情報 | `walk-bittle`・`walk-app`、`walk-core` の調停・`Token`・トークン表・`Transport` trait、実機を動かす実験用の実行ファイル、Cargo のプロファイルを変えたとき |
| `experiment-reviewer` | 実験手順が人だけで再現できるか、判定基準が明確か、安全か | `experimentals/` を変えたとき |

複数に当てはまるときは全部を実行する。互いに独立なので並列に実行してよい。

## 3. 呼び出し方

エージェントに次を渡す。

- 変更の目的（1〜2文）
- 対象の差分（PR のベースブランチとの差分。積み重ねた PR では、前の PR のブランチとの差分）
- 関係する設計書のパス

## 4. 指摘の形式

各エージェントは次の形式で返す。

```
[重大度] ファイル:行 — 指摘
  理由: ...
  提案: ...
```

重大度:

- **blocker**: 直すまで PR を出さない（バグ、テスト無しの振る舞い変更、安全上の問題、設計との食い違いを文書に反映していない）
- **major**: この PR で直す。直さないなら理由を書く
- **minor**: 任意。直さない場合も一言書く

## 5. 人のレビュー

- 人は設計判断（`decisions.md` の変更）と、実機を動かすコードの変更を必ず確認する。
- 実験依頼の PR は、人が実験を行い結果を記入してからマージする（[git-workflow.md](git-workflow.md)）。
